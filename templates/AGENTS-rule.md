## Обезличивание до отправки — обязательный шаг

Никакое содержимое документа не попадает в модель, пока оно не прошло через
`docs-masked`. Это не рекомендация, а порядок работы по умолчанию.

Правило срабатывает, как только в задаче появляется файл с чужими данными:
`.txt`, `.md`, `.docx`, `.pdf`, `.xlsx`, `.csv`, `.json`, `.html`, письма,
выгрузки, анкеты, договоры, резюме, медицинские и кадровые документы, любые
таблицы с людьми.

### Порядок

1. **Обезличить локально.**

   ```bash
   docs-masked scan  <файл>          # что будет скрыто
   docs-masked mask  <файл>          # маска + сейф
   ```

   Полный круг с обращением к модели:

   ```bash
   docs-masked ask <файл> -p "<задача>"
   ```

2. **Проверить, что чисто.** `mask` и `ask` сами вызывают контроль утечки и
   отказываются отправлять текст, в котором остались персональные данные. Если
   проверка не прошла — не обходить её флагом `--force`, а дополнить словари
   (`--terms`) или сообщить об этом пользователю.

3. **Отправлять только замаскированный текст.** В запрос уходят теги
   `#PERSON_1#`, `#PHONE_2#`, `#ADDRESS_1#`, а не оригиналы.

4. **Восстанавливать локально.** Ответ модели проходит обратную подстановку по
   сейфу; замаскированный файл — командой `unmask`.

### Если модель вызывается из кода

```python
from pii_shield import mask_text, assert_clean, unmask_text

r = mask_text(raw_text)
assert_clean(r.text)               # LeakGuardError, если что-то осталось
answer = call_model(r.text)        # наружу уходит только маска
final, _ = unmask_text(answer, r.vault, mode="canonical")
```

### Чего делать нельзя

- Пересказывать содержимое документа в обход маскирования — пересказ несёт те
  же персональные данные.
- Класть оригинальный текст в системный промпт, в имя файла, в комментарий к
  коммиту или в лог.
- Коммитить `*.vault.json` — это ключ к обратной расшифровке.
- Отправлять сейф, журнал отправок или исходные документы во внешние сервисы.
- Использовать `--force` без явного распоряжения пользователя.

### Когда правило не применяется

- Файл заведомо без персональных данных (код, конфиг, документация проекта) —
  но при сомнении сначала `scan`, он бесплатный и локальный.
- Работа с локальной моделью (`--provider ollama`): маскирование остаётся
  рекомендацией как защита от попадания данных в логи, но блокировку можно
  снять осознанно.
